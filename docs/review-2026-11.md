# Review and what next — 2026-11-17

A fresh-eyes review of the whole app, made after M5 (server), M6, Courses C1 and sign-in were merged into `integration`. Three independent reviews fed into it: **UI/UX** (the app run in headless Chromium), **architecture and plan vs reality**, and a **correctness bug hunt**. The goal: Kenning should feel like **one product**, not a set of half-finished features.

Status legend: ✅ fixed in this pass · 🔜 planned next · 📋 backlog.

## 1. Verdict

The foundations are sound:

- `@app/core` is pure, with no UI or IO.
- The storage driver abstraction is clean, and the `/api/rpc` allow-list is small.
- Fetch is injectable everywhere.
- Data integrity checks out. Rebuilds are deterministic, backup import is atomic, and the RPC and SSRF checks are correct.
- There are about 590 TypeScript and 625 Python tests.

The product grew **wide rather than deep**. Reader, Practice, Courses, Converse and Words each work, but they meet only through the learner model, not through learning signals or a shared notion of "my language and my decks". Concretely:

- **Anki decks are one global setting.** One `targetDeck` receives everything: reader, Converse, course words and MCP (MCP even has its own env default). The decks Kenning learns from are re-detected on every sync and never confirmed by the user. A course never gets its own deck. A course deck that detection misses yields no unit words at all.
- **There is no first-run flow.** A new user lands in an empty app and has to find Settings → Sync from Anki.
- **Learning signals don't flow back.** Practice results, reader cloze answers and book exercise answers never change a word's state. Mastering a word in Practice changes nothing in the Reader.
- **The same action is coded in several places.** The domain commands (add / learn next / mark known) live in the web app's services and are re-implemented with different key rules. "Add to Anki" exists four times: reader, Converse, courses and MCP.
- **The plan has quietly diverged.** M6b (weave reading) is 0% done but is called an "M3 leftover". M7 and M8 are not started. The "lite NLP fallback" promised in ADR 0004 does not exist. Several docs are stale (§7).

## 3. UI / UX findings

The screens are calm and consistent with the design system, dark mode is solid, and the Reader (Read / Gloss / Cloze, inspector, Words from this text) is the most finished part. Where it falls apart is **between** screens: each feature has its own words for word states, its own Anki behaviour and its own dead ends.
