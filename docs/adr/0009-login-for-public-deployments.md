# ADR 0009: Sign-in for public deployments

**Status:** accepted (extends ADR 0008)

**Context:** ADR 0008 put all user data in one SQLite file behind `/api`, protected only by an optional bearer token kept in `localStorage`. Users now expose Kenning publicly (Dockge + Cloudflare Tunnel). That needs a real sign-in: a password people can type and password managers can fill, sessions that can be revoked, brute-force protection, CSRF protection, and no XSS-readable secret in the browser. The expensive `/nlp` endpoints (OCR, translation) must not be open to the internet either.

**Decision:**

- **Single user, in `server/api`, no new dependencies** (`node:crypto`, `node:sqlite`). `KENNING_USER` + `KENNING_PASSWORD_HASH`, an scrypt hash (N=2^16, r=8, p=1, 16-byte salt) in the self-describing format `scrypt:N:r:p:salt:hash`. `:` instead of the suggested `$` because Docker Compose interpolates `$` in `.env` and YAML and would silently corrupt a pasted hash (`$` is still accepted when parsing). `node dist/main.js hash-password` reads the password twice without echo; the image uses `ENTRYPOINT` so `docker compose run --rm -it api hash-password` works. A plain `KENNING_PASSWORD` is accepted with a warning (hashed at startup with a username-derived salt, so sessions survive restarts). No password and no token: auth off, logged loudly. No first-run "claim" screen (whoever reaches a fresh server first would own it).
- **Endpoints:** `POST /api/auth/login` (`{user,password}` or `{token}`), `POST /api/auth/logout`, `POST /api/auth/logout-all`, `GET /api/auth/check` (204/401, for nginx `auth_request`), `GET /api/auth/me` (who is signed in). `/api/health` reports `authRequired` and `authMethods`.
- **Sessions:** 32 random bytes, cookie `kenning_session` (`HttpOnly`, `Secure` unless `KENNING_COOKIE_SECURE=0`, `SameSite=Lax`, `Path=/`). Only the SHA-256 is stored, in a separate SQLite file (`KENNING_AUTH_DB`, default `/data/auth.sqlite`), so backup export/import never contains or replaces sessions. 30-day sliding expiry (renewed at most every 5 minutes, cookie re-sent), 180-day absolute maximum. Each session records a fingerprint of the credential that created it: changing the password, username or token ends those sessions. Secrets are compared in constant time (both sides hashed, then `timingSafeEqual`); a wrong username still runs scrypt; error messages are generic. scrypt runs one at a time to bound memory under a flood.
- **Brute force:** per client IP, three free failures, then 1 s, 2 s, 4 s ... up to 15 min; plus a global cap of 100 failures per 15 minutes. The global cap lets an attacker lock the owner out for a window; for a single-user app that is preferable to unbounded distributed guessing. Wrong bearer tokens count too. The client IP is `CF-Connecting-IP` only with `KENNING_TRUST_CF=1`, else nginx's `X-Real-IP`. State is in memory.
- **CSRF**, in every mode (also with auth off, where a foreign page could otherwise POST a backup import to `localhost`): non-GET requests need `Content-Type: application/json` or `X-Kenning: 1`, an `Origin` (when present) matching `Host` or `KENNING_ALLOWED_ORIGINS`, and no `Sec-Fetch-Site: cross-site`. Requests with an `Authorization` header are exempt (cannot be sent cross-site without a preflight this server never grants).
- **Bearer `KENNING_TOKEN`** keeps working for scripts and `apps/mcp` (which now also sends it to `/nlp`); in the browser it can be exchanged for a session on token-only servers. The browser no longer stores any token.
- **nginx** (`deploy/nginx.conf.template`): `auth_request` to `/api/auth/check` on `/api/*` (except `/api/health`, `/api/auth/*`) and on `/nlp/*`; refusals answer JSON 401. The api checks again itself. Security headers at server level: CSP (`script-src 'self' 'wasm-unsafe-eval'`, `frame-ancestors 'none'`; `connect-src *` because AnkiConnect, AI providers and the NLP address are user-chosen), `nosniff`, `X-Frame-Options`, `Referrer-Policy: same-origin`, COOP, Permissions-Policy.
- **No api container** (browser-mode setups): `/api/health` fails as before, so the app uses browser storage. For `/nlp` the gate fails _closed_; the web image has `KENNING_NLP_AUTH=on` and an api-less setup sets `off` explicitly (rendered by the nginx image's envsubst template step, filtered to `KENNING_*`). Failing open on a 502 was rejected: a crashed or restarting api would expose the NLP service publicly.
- **Web:** a sign-in screen in the design system. Startup (`storage/startup.ts`): auth required and 401 means sign-in, never browser storage; a server this browser used before that does not answer gives an outage screen instead of a new empty local database. A later 401 from `/api` or `/nlp` (fetch watch) lays the sign-in over the mounted app, so route and input survive, then refetches. Settings > Account: signed in as X, sign out, sign out all devices.
- **Deployment:** `deploy/dockge/compose.yaml` (GHCR images only, internal network for the api, healthchecks, optional pinned `cloudflared` under profile `tunnel`, public hostname to `http://web:80`).

**Consequences:**

- Public self-hosting is reasonable without extra infrastructure; Cloudflare Access can still be layered in front.
- One user only. Multi-user would need per-user data, which the single event log does not have.
- Rate-limit state is lost on restart, and per-IP limits depend on correct `KENNING_TRUST_CF`.
- Scripts doing state-changing requests with auth off must send `X-Kenning: 1`.
